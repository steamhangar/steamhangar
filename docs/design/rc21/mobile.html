SteamHangar on a phone MOBILE-1a · rc21 · design only

Phone fine-tuning on top of the rc20 kit (docs/design/rc20/kit.html, web/css/kit.css). Frames are 390 px (iPhone 15) and 400 px for the pairing flow, one landscape frame at 844×390. Everything uses the kit's class names and the token values of theme.css; the few new values are listed at the end. Each frame's note names the CSS rule it implies. Sample data is illustrative; copy comes from web/js.

1 · Touch targets @media (pointer:coarse)

Every control below 44 px gets a 44 px hit area on touch screens. The visual grows only to the existing 38 px toolbar height (.lib-tools .btn, .sortg), the rest is an invisible extender, so the phone layout keeps its density. Mouse users see no change: the rules sit in @media (pointer:coarse), the complement of the existing (hover:hover) and (pointer:fine) blocks. Frames 1b–1d show the coarse sizes on real pages with the hit areas tinted.

2 · Scrolling segs with an overflow cue mask-image edge fade

A seg never wraps (kit rule), so on a phone the seven Downloads ranges and the seven Library chips scroll sideways. Today nothing says so. Proposal: a 32 px (--sp-7) edge fade on the side that has more, and the row is laid out so the last visible item is cut, never flush with the edge. The pressed item is scrolled into view on load (scrollIntoView({inline:"nearest"})).

3 · Bottom sheets .sheet on a phone

Below --w-sheet every sheet is a bottom sheet: full width, top radius --r-xl, grab handle, max height 88 % of the dynamic viewport. Header and tabs stay put, only the body scrolls, the action row sits on the safe area. The centred .dialog confirms become bottom sheets too, with the safe choice nearest to the thumb.

4 · QR pairing at 400 px Clients → Add a device

The drawer from ADD-DEVICE-2 as a full-height bottom sheet at 400 px. The QR stacks above its buttons (the existing @container addev (max-width:420px) rule) and grows to 200 px so a second phone can scan it from arm's length. Taps marked .

5 · Safe-area insets env(safe-area-inset-*)

index.html already sets viewport-fit=cover, so the page runs under the status bar and the home indicator. The bottom nav and the bulk bar already add env(safe-area-inset-bottom); the top inset is not handled yet. Hatched bands = the insets of an iPhone 15 (47 / 34 px).

6 · 200 % text and landscape intrinsic sizing

Android's font-size setting and browser text zoom scale every --fs-* token. The frame below doubles them. Nothing may clip: stats fall back to fewer columns by an em minimum, buttons wrap, the nav label ellipsizes.

Proposed CSS summary for MOBILE-1b

Not final code: the shape of the rules the frames imply, so the implementation is mostly CSS. Names follow kit.css / app.css; the mockup itself fakes pointer:coarse with a .coarse class and the insets with fixed numbers.

Decisions operator, 2026-10-18

  1. Q1 Coarse visual size: Weg A. Visuals grow to 38 px (--ctl-h), the hit area is 44 px (--hit) by an invisible ::after extender.
  2. Q2 Which edge fades: Weg B. A small shared scroll listener toggles .at-start/.at-end on every .scue (works in every browser, one unit test).
  3. Q3 Confirms: all .dialog confirms become bottom sheets below 600 px (one rule in app.css).
  4. Q4 History row: Weg A. On phones a tap opens the row's panel in a bottom sheet (3d).
  5. Q5 Pairing on the same phone: on a narrow touch screen the Phone tab leads with a full-width primary "Open on this phone"; the QR follows as "Pair another phone" (4b, 4c). Desktop keeps the QR first.
  6. Q6 Pairing success: accepted as is. No "paired" state in the drawer; that needs per-device keys (PAIR-2).
  7. Q7 Landscape nav: icon and label side by side, --nav-h 48 px (6b).
